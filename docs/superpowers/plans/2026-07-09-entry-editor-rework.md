# Entry Editor Rework Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax. Unlike earlier plans, UI steps here give exact behavioral contracts + anchors rather than verbatim components — read the current files first; per-task reviews gate the result.

**Goal:** Rework the entry editor per David's testing feedback: task lines become fragment + hours (task-code dropdown hidden behind an opt-in affordance), the narrative becomes a live-AUTO editable box with edit-through back into the lines, AI actions merge into the narrative box (Expand/Shorten/Rewrite dropdown; split-into-tasks unchecked by default), the client is shown in the modal, and a per-client **task-billing flag** controls whether consolidated narratives carry `(0.x)` allocations — enforced as a finalize warning.

**Architecture:** One migration (`clients.task_billing`, default 1 = today's behavior). Narrative generation grows a `taskBilling` mode on both the server (`server/lib/narrative.js` → `syncNarrative`) and the client mirror. A new zero-import browser lib (`public/js/lib/narrativesync.js`, unit-tested) owns generate + parse-back for the two-way AUTO binding. The editor consumes `entry.cm.client_task_billing` + `client_name` added to `loadEntry`'s cm payload.

**Tech stack / constraints:** unchanged — Node 24 ESM, Express 5, better-sqlite3, node:test, no-build React 18 UMD + htm; runtime deps exactly express + better-sqlite3; migrations append-only positional; export/CSV/.TIM and `/api/cms` response field names unchanged (ADDITIVE fields are fine); tests never need live Ollama; `npm test` green per task, frontend tasks end with e2e `ALL CLEAR`. Branch: `entry-editor-rework`.

## Binding decisions (David, 2026-07-09)

- Narrative model: **live AUTO with a toggleable AUTO button**. AUTO ON: box shows the generated consolidation and is EDITABLE; edits within a task's segment feed back into that task line (fragment, and duration if the parenthetical was edited). If an edit breaks the segment structure (delimiters/count no longer parseable), AUTO toggles OFF automatically and the text stands as manual narrative. AUTO OFF: plain manual narrative; toggling back ON regenerates from the lines (overwriting the manual text).
- Task-billing flag: **format + finalize warn**. Task-billing clients (flag=1): consolidation includes `(0.x)`; finalize WARNS (not blocks) when a multi-task entry's narrative lacks allocations. Block-billing clients (flag=0): consolidation joins fragments with `; ` WITHOUT parentheticals; no allocation warning.
- `split into tasks` default: unchecked.
- Default for existing/new clients: `task_billing = 1` (preserves today's `(0.x)` behavior exactly; David flips block-billed clients off himself).

### Task 1: Server — `clients.task_billing` flag, generation mode, finalize warn

**Files:** `server/db.js` (append NEXT migration), `server/lib/narrative.js`, `server/routes/entries.js` (`syncNarrative`, `loadEntry` cm payload), `server/routes/clients.js` (PATCH accepts flag), `server/routes/cms.js` (list rows carry it — check `CM_COLS`), `server/lib/validation.js` + wherever finalize warns assemble. Tests: `test/db.test.js` (append migration test + fix the replay-simulation tests, which must now also undo this migration — see the existing pattern comments there), `test/narrative.test.js`, `test/api.entries.test.js`, `test/api.clients.test.js`, `test/api.finalize.test.js`.

**Interfaces produced:**
- Migration (append at END of MIGRATIONS): `ALTER TABLE clients ADD COLUMN task_billing INTEGER NOT NULL DEFAULT 1;` with a comment: per-client billing style (1 = task-billed, allocations in parens; 0 = block-billed).
- `buildNarrative(lines, { increment, taskBilling = true })` — when `taskBilling` false, join cleaned fragments with `; ` + trailing period, NO parentheticals (same ≥2-substantive-lines rule; otherwise null).
- `syncNarrative` resolves the entry's matter → client `task_billing` (LEFT JOIN; null client → default 1) and passes it through.
- `loadEntry`'s `cm` object gains `client_name` and `client_task_billing` (additive; matter with no client → `client_task_billing: 1`, `client_name: null`).
- `PATCH /api/clients/:id { task_billing }` → 0/1 coerced; `GET /api/cms` rows gain `client_task_billing` (additive to `CM_COLS`' client join).
- Finalize warn: for a task-billing client, an entry with ≥2 substantive task lines whose narrative contains NO `(0.x)`-style allocation gets `warns.push({ level:'warn', code:'missing_allocations', message:'This client requires task billing — add per-task time allocations, e.g. "(0.5)".' })`. Detection regex: `/\(\s*\d+(?:\.\d+)?\s*\)/` on the narrative. Block-billing clients: no such warn. (Wire it wherever existing warns are computed so both `/finalize` and `/finalize-day` see it — follow `banned phrases` precedent.)
- TDD throughout; verify replay tests in `test/db.test.js` still pass (they simulate old DBs and must drop this column too — `ALTER TABLE clients DROP COLUMN task_billing` in their teardown blocks, rollback counts bumped).

### Task 2: `public/js/lib/narrativesync.js` — generate + parse-back (pure, unit-tested)

**Files:** create `public/js/lib/narrativesync.js`, `test/narrativesync.test.js`. Then refactor `public/js/ui.js`'s `previewNarrative` to delegate to it (keep the export name working — grep call sites).

**Interfaces produced (zero imports; consumed by Task 3):**
- `generateNarrative(lines, { increment = 0.1, taskBilling = true }) → string | null` — client mirror of the server rule: lines = `[{ fragment, task_code, duration }]`; substantive = trimmed fragment/task_code text or duration > 0; < 2 substantive → null; text per line = cleaned fragment || task_code || 'Time', first letter of first segment capitalized; task-billed: `` `${text} (${hours})` `` joined `; ` + `.`; block: `${text}` joined `; ` + `.`. Hours formatting must match ui.js `fmtHours` output for the increment (copy the minimal formatting logic in — zero imports — and add a drift test comparing against a fixture table).
- `parseNarrativeEdit(text, lineCount, { taskBilling = true }) → { segments: [{ fragment, duration|null }] } | null` — the edit-through parser. Task-billed: split on segments shaped `<text> (<num>)` separated by `;` (tolerate the final `.`); returns null unless exactly `lineCount` segments each with a parseable parenthetical. Block: split on `;` (tolerate final `.`); null unless exactly `lineCount` non-empty segments; `duration: null` for all. Whitespace trimmed; a segment's fragment may legitimately contain parentheses in task-billed mode ONLY if a trailing `(num)` still terminates it (regex anchor the LAST parenthetical per segment).
- Tests: round-trip property (generate → parse returns the same fragments/durations, both modes); edit-one-fragment; edit-one-duration; structural breaks return null (deleted paren, merged segments, added segment, empty text); block-mode with user semicolons inside a fragment → null (count mismatch) — that's the detach signal, by design.
- `rebalanceHours(durations, changedIndex, newValue, { total, increment = 0.1 }) → number[]` — David's auto-rebalance rule (deliberately simple): line `changedIndex` gets `newValue` (rounded to the increment, min increment); the DELTA vs. its old value is absorbed by the OTHER lines in reverse order (last line first), each floored at one increment; whatever cannot be absorbed just changes the effective total (no error, no redistribution gymnastics). Pure, increment-safe (work in integer tenths internally to dodge float drift). Tests: simple pull-from-last; pull spanning two lines; floor-at-0.1 leaves remainder unabsorbed (total grows); decrease case (delta returns to the last line); single-line no-op.
- `formatSuggestion(text) → string` — fully-formed narrative formatting shared by StopChips and the editor's suggestion chips: trim, capitalize first letter, ensure exactly one trailing period (don't double up after `.`/`!`/`?`).

### Task 3: Editor rework + e2e

**Files:** `public/js/components/entryeditor.js`, `public/css/app.css`, `scripts/e2e-smoke.mjs`. Read the whole component first.

**Behavioral contract:**
1. **Task lines** (anchor: the task-line map): visible per line = drag/sort affordances as-is, `GhostInput` fragment, hours input, delete — NO task-code `<select>`. Per line, a small ghost affordance shows the code as a removable chip when set (`Review ✕`) or a muted `+ code` button when unset; clicking `+ code` reveals an inline select (existing `taskCodes` list) that collapses back to chip on choose. `task_code` stays in state/API untouched (architecture kept).
2. **AUTO narrative box**: replace the current `isAuto ? readOnly textarea : GhostInput` split with ONE editable surface + an `AUTO` toggle chip in the Narrative section-title row.
   - AUTO available only when `generateNarrative(lines, { taskBilling }) !== null` (≥2 substantive lines); `taskBilling` from `local.cm.client_task_billing ?? 1`. When unavailable, the toggle is hidden and the box is a plain manual GhostInput (today's single-line behavior, ghost + shortcuts intact).
   - AUTO ON (default whenever it's available AND the stored entry was auto — mirror the current `narrative_auto` semantics so existing entries open the same way): box value = generated text, EDITABLE (plain textarea is fine in AUTO mode — ghost/shortcuts stay for manual mode). On input, run `parseNarrativeEdit(text, lineCount, { taskBilling })`: parse OK → write fragments (+ durations when non-null and changed) back into `local.tasks` (single `update()` batch; guard against feedback loops by comparing before set); parse null → set AUTO OFF and keep the user's text as the manual narrative.
   - AUTO OFF: manual GhostInput narrative exactly as today (`update({ narrative })`); persistence unchanged (the server's `narrative_auto` handling must keep working — check how `doPersist`/PATCH treats narrative when lines exist; the server re-syncs auto narratives, so when AUTO is ON simply DON'T send a manual narrative override, matching today's auto path).
   - Toggling ON regenerates from lines (discarding manual text after the same silent rule as today — it's one click to get back).
3. **AI merge** (anchor: the `ai-row`): delete the separate brief input. The narrative section-title row gains the AI button (sparkles) with a small dropdown (ContextMenu or a tiny popover, follow existing patterns): **Expand** (mode `draft`, `brief` = current narrative text), **Shorten** (`shorter`), **Rewrite** (`regenerate`) → all stream into the narrative via the existing `aiNarrate` machinery (keep abort/supersede logic intact). Button disabled when the narrative is empty or AUTO is ON (AI writes manual text; using it while AUTO is available should first flip AUTO OFF — acceptable: clicking AI when AUTO is ON toggles AUTO OFF and uses the generated text as the seed). Keep the `split into tasks` option as a checkbox inside the dropdown (or beside the button) using `/ai/expand` with `brief` = narrative text — **default UNCHECKED** (`useState(false)`).
4. **Client in the modal**: next to/under the CM picker line show `client_name || client_number` (from `local.cm` — Task 1 added `client_name`; the picker's own selection payload may lack it, so fall back gracefully or refetch the entry row on pick).
4b. **Suggestion chips in the editor** (David 2026-07-09 addition): the same suggested narratives the StopChips popup offers must also appear in the edit modal — a compact tappable chip row near the narrative box (visible when the narrative is blank/manual and suggestions exist; reuse `useMatterSuggestions`, dedupe, max 3, filter `containsTimeAmounts`). Tap = set the manual narrative to the chip text. ALL suggestion chips — here AND in stopchips.js — render **fully-formed** via `formatSuggestion` (capitalized, trailing period), and the formatted text is what gets filed/inserted.
4c. **Hours auto-rebalance** (David 2026-07-09 addition): when a line's hours input changes, run `rebalanceHours` over the durations with `total` = the entry's current total (`total_override` ?? sum before the edit) and apply the returned durations to the lines in one update. The allocated-vs-total row keeps showing any residual mismatch as it does today.
5. **e2e**: update every step that touched the old selectors (brief input, `.narrative-preview textarea` when auto, AI row, ghost step). Add: (a) two-line entry on a task-billing client → AUTO box shows `frag1 (0.x); frag2 (0.y).`; edit `frag2`'s text in the box → the second line's fragment input updates; (b) delete a parenthetical → AUTO chip turns off and text stays; (c) `+ code` affordance sets a task code on a line; (d) the client label is visible in the modal. Keep the suite green end-to-end.

**Out of scope:** Clients & Matters screen UI for flipping the flag ships in Task 1 only as the API; add a small checkbox in the C&M client row / client-name edit modal IF trivial (implementer's call, ≤20 lines) — otherwise note it for follow-up.
